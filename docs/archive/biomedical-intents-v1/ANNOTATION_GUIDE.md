# 人工相關性判讀指南

本指南為正式人工評估提供一致的起點。使用者已於 **2026/10/15 確認研究對象範圍：依查詢意圖納入人體、動物與細胞研究，理由註明研究類型**；其餘共通準則與逐查詢納排細節仍是待確認的建議，不代表整份指南已核可。判讀由使用者閱讀摘要後完成；本文件不產生人工標籤，也不將規則弱標籤或 AI 判斷當作標準答案。固定使用本專案 3,000 篇快照及 `data/queries.json` 的十個查詢，不因標註方便而更改查詢文字、意圖或概念群組。

## 1. 先固定判讀範圍

研究對象範圍已確認；其餘共通界線建議先確認，再開始大批標註。若中途改變準則，記錄變更，重新檢視受影響的舊判讀。

| 判讀界線 | 已確認範圍／建議起點 |
|---|---|
| 評估依據 | 以本快照收錄的摘要能提供的資訊判斷；標題輔助辨識文章，不能僅憑標題補出摘要沒有的證據。 |
| 研究對象 | **已確認（2026/10/15）：依查詢意圖納入人體、動物與細胞研究，理由註明研究類型。** 這項確認不等於每一篇此類研究都相關；仍須依摘要內容與查詢意圖判斷。 |
| 研究類型 | 原始研究與直接整理該問題的綜述均可相關；僅有背景提及不足以構成相關。理由標明研究類型。 |
| 結果方向 | 正向、無效果、負向或有害結果均可相關；判斷是否回答資訊需求，不判斷是否支持預期結論。 |
| GLP-1 類別範圍 | Q04–Q10 暫容許摘要明確建立 GLP-1、其受體或相關治療與指定主題之關係；僅提到其他代謝藥物不自動納入。具體藥物或複合機轉是否納入需先確認。 |
| 直接與間接證據 | 主要研究問題直接回答資訊需求可為 2；提供實質但局部的關聯可為 1；只有共同出現的詞或背景描述為 0。 |
| 證據不足 | 暫存為 -1，理由說明缺少的資訊或待釐清事項；不能為完成進度而改成 0。 |

這是檢索相關性作業，不是療效推薦。相關不等於研究品質高，也不等於結果具有臨床適用性。若要另評研究品質，應增加獨立紀錄，不混入本次相關等級。

## 2. 四個等級與決策順序

| 等級 | 定義 | 何時使用 |
|---|---|---|
| -1 | 未標註／尚未完成判斷 | 尚未讀完、資訊不足、專業界線待確認，或需要重新檢視。不是負例，也不算完成判讀。 |
| 0 | 不相關 | 已閱讀，摘要不能實質回答該查詢的資訊需求；只在背景提及、研究主體不同，或不符合已固定的納排範圍。 |
| 1 | 相關 | 對資訊需求有可指出的實質內容，但只涵蓋部分面向、屬次要分析，或與需求的連結較間接。 |
| 2 | 高度相關 | 資訊需求是摘要的主要問題或主要分析，且摘要提供直接的結果、機轉或綜整內容。 |

每篇依序確認：

1. 對照該查詢的 `intent`，確認需要回答的關係。不要把查詢文字的每個詞都當成必要條件。
2. 閱讀完整摘要，找出研究主體、研究對象、主要問題與結果。
3. 先判斷是否有足夠資訊；不足則保留 -1 並記錄疑點。
4. 有足夠資訊但沒有實質關聯，標 0；有實質關聯，再依主要／次要程度區分 2／1。
5. 寫下足以讓另一位讀者重現判斷的理由，再儲存。

相同 PMID 在不同查詢可有不同等級。不要因檢索分數高、排名靠前、命中詞多、期刊熟悉，或弱規則給了標籤而直接判相關。`queries.json` 中的 `groups` 是弱規則用的公開概念群組，不是人工判讀的必要或充分條件；人工判讀可以辨認同義表達，也可以將所有概念詞都有出現的文章判為 0。

### 1 與 2 的一致性

先試讀每個查詢數篇文件，保留可作參照的 0／1／2 案例及理由。完成一批後，回看同查詢先前的 1、2，確認沒有因疲勞或印象而逐漸放寬標準。若仍無法區分，先保留 -1 並列出待決事項；不要為增加高度相關篇數而上調。

## 3. 理由寫法

建議每筆以一至三句包含以下資訊：

> 【研究對象／類型】摘要主要探討……；與本查詢的關係為……，依據是摘要的……結果或敘述；因此判為……。若有限制：僅涵蓋……／未提供……。

可直接改寫以下範本，必須替換成實際讀到的內容：

- **2：**「【對象／研究類型】主要分析［指定主體］與［指定結果／機轉］的關係；摘要報告［具體發現，含無效果結果亦可］，直接回答本查詢。」
- **1：**「【對象／研究類型】主要問題為［其他主題］，但摘要另報告［與本查詢有關的具體內容］；因［僅為次要結果／僅回答其中一部分］判為相關。」
- **0：**「【對象／研究類型】主要分析［實際問題］；［查詢主體］僅在背景提及，摘要沒有提供其與［所需主題］的實質關係。」
- **-1：**「已閱讀，但摘要未交代［必要資訊］／［納排界線］尚待確認，目前無法完成判斷。」

「有關」「有 GLP-1」「分數很高」「沒有命中」不足以作為理由。若簡短引用摘要，需指出所支持的判斷；不必抄錄整段摘要。理由只紀錄文件內容，不補造摘要未提及的結果。

## 5. 候選池與池外補查

### 建立候選池

1. 固定語料快照、查詢、前處理與 IDF 設定；建議先採既有預設 C＋標準 IDF。
2. 對每一個查詢，取原五種 weighting 與第六種 BM25 各自 Top 20 的 PMID 聯集並去重。這是「每方法最多 20 篇」，不是每查詢固定 120 篇；方法重疊或有效結果不足時會更少。
3. 記錄候選池的設定、建立日期、查詢及語料 SHA256、每查詢池大小。所有方法共用同一份人工判讀，避免只標註某一方法找出的結果。
4. 依穩定順序閱讀，盡可能先看完整摘要再參考排名與分數，以降低排序造成的期待。不要以弱標籤結果決定等級。
5. 若新增前處理／IDF 比較，檢查新設定是否帶來尚未判讀的文件；可擴大共同候選池並補讀，保留原有判讀與來源紀錄。

### 池外補查

- 使用介面的全語料閱讀，補查候選池外可能相關的摘要；可依主題的同義詞、指定藥物、結果或機轉有目的地尋找。
- 池外找到的相關文件也應記錄 `qid, pmid, grade, reason`；同時在研究紀錄註明「池外補查」及補查方式。
- 補查到的不相關文件若已實際閱讀，也保留 0 與理由。尚未閱讀的文件仍為 -1。
- 先完成每查詢的共同候選池，再補查池外，是可行的工作起點；只讀 Top 10 很難支持對完整語料的相關集合描述。
- 若時間不足，明確列出已讀池大小、池外已讀數及未讀數，不能聲稱已完成全語料判讀。

候選池由被比較的詞彙方法產生，可能漏掉所有方法都未找出的相關文件，即 pooling bias。池外補查可降低此限制，不能保證消除它。比較報告需保留候選池深度、設定與補查方式；不要把未讀文件列為人工負例。

## 6. 進度狀態與可宣稱範圍

對每個查詢分開記錄「已判讀數（0／1／2）」「未完成數（-1）」「已知相關數（1／2）」與判讀範圍。

| 狀態 | 判定 | 必須同時呈現的限制 |
|---|---|---|
| 尚未標註 | 沒有任何完成的 0／1／2 判讀 | 不能當作沒有相關文件。只有 -1 的紀錄仍屬此類。 |
| 已判讀但未找到相關文件 | 至少有一筆 0，且目前沒有任何 1／2 | 只表示「在目前已判讀範圍未找到」；顯示已讀／範圍總數及是否仍有未讀文件。 |
| 已有相關文件 | 至少有一筆 1 或 2 | 顯示已知相關數與未讀數；已有正例不代表候選池或全語料判讀完成。 |

「候選池已讀完」與「全語料已讀完」是另一個進度維度，不應由有無正例推定。即使候選池全部判為 0，也不能推論 3,000 篇語料沒有相關文件；若全語料均已依固定準則判讀，才可限定為「本快照、此準則下未找到相關文件」。

## 7. 儲存、版本與正式評估前檢查

人工標註保存於 `data/judgments/manual.json`，CSV 欄位為 `qid,pmid,grade,reason`。在改換查詢、設定、頁面或匯入前，先確認目前編輯是否已儲存；以畫面成功回饋及重新載入後的值確認，不把文字框已填寫當作已寫入檔案。匯入或大批修改前先匯出備份，保留既有人工成果。既有資料的語料／查詢 hash 不符合時，先釐清版本，不直接套用。

正式評估前逐項確認：

- 十個查詢均有已記錄的資訊需求與判讀界線；全部完成所宣告的閱讀範圍，且每筆已判讀資料都有理由。
- 逐查詢列出判讀範圍、已判讀數、未完成數、0／1／2 數量與已知相關總數；有疑問的 -1 不冒充負例。
- 記錄語料、查詢、人工標註版本與 hash，以及評估用的 weighting、前處理、IDF、k 與候選池深度。
- 人工評估輸出與 `weak_rules` 分流。未完成正式標註時，弱標籤仍只作流程示範。
- 報告固定查詢總數為 10，另列實際納入平均的查詢數及每個排除原因。現有指標只對有已知相關文件的查詢納入平均；例如只納入 3 個，就寫 3／10，不能稱為十查詢整體表現。
- 對「尚未標註」和「已判讀但未找到相關」分別揭露，不能用同一個空白平均值掩蓋兩者。
- 未標註文件在現有指標計算中暫按 0 處理，是計算約定，不是人工不相關判斷；同步報告 judged@k。
- 標註不完整時，Recall@k 的分母是已知相關文件數，只能稱為相對於已知相關集合的 Recall。P@k、MRR 與 nDCG 也會受漏標影響；相似度分數不稱為正確率。

可放入正式報告的方法敘述範本：

> 本研究在固定 3,000 篇摘要快照上使用十個查詢。人工依［已確認準則版本］判讀六方法各 Top 20 聯集，並以［方式］補查池外文件。總計完成［數量］個查詢的［判讀範圍］，有已知相關文件且納入平均者為［數量］／10；其餘查詢分別因［尚未標註／目前已讀範圍未找到相關／其他原因］排除。未讀文件不視為人工負例，計算時暫按 0，並附 judged@k。Recall 僅相對於已知相關集合；候選池及不完整判讀可能影響方法比較。

方括號內容需由實際紀錄填入；未完成前保留待補，不預填漂亮數字或預設 TF-IDF 勝出。
